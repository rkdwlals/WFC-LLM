# LLM 기반 WFC 제약 생성을 통한 프롬프트 기반 장애물 배치

"서쪽은 빽빽하게, 동쪽은 비워 줘"처럼 말로 지시하면, 강·연못을 침범하지 않고 출발점에서 도착점까지 길을 남기는 장애물 배치 초안을 만드는 도구입니다.
LLM은 명령의 의도를 JSON 제약으로 바꾸고, 실제 배치는 규칙 기반 WFC(Wave Function Collapse)가 맡습니다.

- 1인 연구·개발 (순천향대학교 메타버스&게임학과, 지도교수 지도)
- 2026 학술제 본선 출품, 2026 AI.SW 프로젝트 경진대회 장려상
- Unity 6 (6000.3.2f1), C#, Ollama, gemma4:e4b
- 포트폴리오 상세: https://rkdwlals.github.io/projects/llmwfc.html

## 구조

```
자연어 명령
   │
   ▼
LLM (LlmPrompting.cs, LlmApi.cs)
   │  3×3 구역별 밀도(low/mid/high), 장애물 종류 비중, 경로 필수 여부를 JSON으로 출력
   ▼
제약 검사 (Criteria.cs)
   │  형식·값 범위를 검사해 어긋난 항목만 기본값으로 교체
   ▼
WFC 배치 (ObstacleWfc.cs)
   │  물·다리·시작점·목표점 고정 → 경로 선확보 → 칸별 가중치
   │  → 인접 규칙을 지키며 칸 확정·전파 → 실패 시 seed를 바꿔 최대 20회 재생성
   ▼
장애물 맵 + 지표 계산 (PathMetrics.cs)
```

LLM은 맵을 직접 그리지 않고 제약만 만듭니다. 그래서 인접 규칙과 지형 침범은 LLM 출력과 상관없이 WFC가 보장합니다.

## 실험

### 설계

개발 전에 지표와 비교 대상을 먼저 정했습니다.

- **목표 맵 20개:** 패턴과 장애물 종류 조합을 바꿔 WFC로 생성
- **명령어:** 정답을 모르는 별도 에이전트(Claude Sonnet)가 목표 맵 그림만 보고 작성. 숫자 0건
  - 서술형: 레벨 디자이너처럼 1~3문장
  - 명시형: 구역·종류를 명시
  - 새 문체(보류 시험셋): 키워드 규칙 사전을 고정한 뒤에 새로 작성. 구어체(H1), 기획서체(H2)
- **비교 조건**

| 조건 | 내용 |
| --- | --- |
| B0 | WFC 단독 (LLM 없음) |
| B1 | LLM이 맵을 직접 생성 |
| B2 | 키워드 규칙으로 명령을 제약으로 변환 (LLM 없음) |
| A1, A3 | 제안 기법에서 구역 밀도 / 보정 힌트를 뺀 절제 실험 |
| Zero-shot, Few-shot | 제안 기법 |
| 상한 | 정답 파라미터를 그대로 넣은 경우 |

- **주요 지표:** 구역 밀도 오차(3×3 구역별 장애물 밀도의 목표 맵 대비 평균 절대 오차), 블록 밀도 오차, 종류 비중 차이, 인접 규칙·금지 위치 위반, 경로 확보 비율
- **통계:** 목표별 쌍체 Wilcoxon 부호순위 검정, Holm 보정, bootstrap 신뢰구간
- **모델 선정 파일럿:** 8GB GPU에서 도는 공개 모델 3종(exaone3.5:7.8b, gemma4:e4b, qwen3.5:9b)을 비교해, 형식을 모두 지키고 가장 빠른 gemma4:e4b를 선택 (`Experiment/pilot`)

### 결과 (본실험, gemma4:e4b, `Experiment/v2/analysis/summary.md`)

| 명령어 | B0 (WFC 단독) | B2 (키워드 규칙) | Zero-shot (제안) | 상한 |
| --- | --- | --- | --- | --- |
| 서술형 | 0.201 | 0.109 | 0.107 | 0.046 |
| 명시형 | 0.201 | 0.054 | 0.057 | 0.046 |
| 새 문체-구어체 | 0.201 | 0.193 | 0.123 | 0.046 |
| 새 문체-기획서체 | 0.201 | 0.201 | 0.124 | 0.046 |

구역 밀도 오차, 낮을수록 좋음. 목표 20개 평균.

- WFC 단독 대비 구역 밀도 오차 47% 감소 (서술형, 0.201 → 0.107, Holm 보정 p = 0.004)
- 처음 보는 문체에서 키워드 규칙 대비 36~38% 감소 (구어체 p = 0.004, 기획서체 p = 0.005, Holm 보정)
- 사전을 만들 때 본 서술형·명시형 명령에서는 키워드 규칙과 유의한 차이가 없음 (Holm 보정 p = 1.0)
- JSON 형식·스키마 준수 100% (응답 360개). 인접 규칙·금지 위치 위반 0, 경로 확보 100% (서술형 맵 1,200개)
- LLM 직접 생성(B1)은 형식 준수 0%, 금지 위치 위반 맵 65%, 경로 확보 63%

비교 모델 qwen3.5:9b 결과는 `Experiment/v2_qwen`에 있습니다.

## 한계

- 목표 맵을 이 시스템의 WFC로 만들었고, 명령어도 AI 에이전트가 작성했습니다. 사람이 만든 맵과 레벨 디자이너의 실제 명령으로 다시 검증해야 합니다.
- 지표(구역 밀도 오차 등)가 사람이 보는 "명령을 잘 따랐는가"와 얼마나 맞는지는 아직 확인하지 않았습니다.
- 새 베이스 맵에서는 경로 확보 비율이 떨어지는 경우가 있습니다.
